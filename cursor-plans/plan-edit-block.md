# Plan: Редактирование блоков в AdminPanel

## Контекст

Расширение существующей AdminPanel: после того как пользователь перетащил блок на холст, он должен иметь возможность **кликнуть на блок** и отредактировать его данные через форму в боковой панели. Форма строится с помощью `react-hook-form` и UI-компонентов `shadcn/ui`. Новые зависимости не устанавливать.

---

## Чеклист задач

### 1. Подготовка — изучи существующий код

- [ ] Открой `/types/blocks` — изучи все типы/интерфейсы блоков. Обрати внимание на поля каждого блока (строки, числа, булевы, массивы, вложенные объекты и т.д.).
- [ ] Открой компоненты в `/components/shared`, `/components/EventPlan`, `/components/Place` и остальных папках — посмотри, какие `props` принимает каждый компонент.
- [ ] Убедись, что `react-hook-form` есть в `package.json`. Найди также доступные компоненты `shadcn/ui` в проекте (обычно лежат в `components/ui`) — используй **только уже существующие** компоненты shadcn, не устанавливай новые.
- [ ] Посмотри на текущую реализацию `AdminPanel`, чтобы понять где и как хранится state блоков на холсте.

---

### 2. Обнови state холста

- [ ] В state каждого размещённого блока добавь поле `props` — объект, хранящий текущие значения редактируемых данных блока. Пример структуры:
  ```ts
  interface PlacedBlock {
    id: string; // уникальный id экземпляра на холсте
    type: string; // тип блока (например, "EventCard")
    props: Record<string, any>; // текущие значения полей блока
  }
  ```
- [ ] При добавлении блока на холст инициализируй `props` дефолтными значениями (пустые строки, false, пустые массивы — в зависимости от типа поля из `/types/blocks`).

---

### 3. Добавь выделение блока на холсте

- [ ] Добавь в state переменную `selectedBlockId: string | null` (изначально `null`).
- [ ] При клике на блок на холсте — устанавливай `selectedBlockId` в `id` этого блока.
- [ ] Визуально выделяй выбранный блок (например, обводкой через Tailwind-класс `ring-2 ring-primary`).
- [ ] При клике на крестик в панели редактирования — сбрасывай `selectedBlockId` в `null`.

---

### 4. Создай компонент BlockEditor

- [ ] Создай файл `components/AdminPanel/BlockEditor.tsx`.
- [ ] Компонент принимает пропсы:
  ```ts
  interface BlockEditorProps {
    block: PlacedBlock;
    onSave: (id: string, props: Record<string, any>) => void;
    onClose: () => void;
  }
  ```
- [ ] Компонент рендерится в правой боковой панели AdminPanel, когда `selectedBlockId !== null`.
- [ ] Если `selectedBlockId === null` — панель скрыта или показывает заглушку "Выберите блок для редактирования".

---

### 5. Реализуй форму внутри BlockEditor с react-hook-form

- [ ] Импортируй `useForm` из `react-hook-form`.
- [ ] Инициализируй форму с `defaultValues` из `block.props`.
- [ ] Для каждого поля блока (из `/types/blocks`) динамически рендери нужный UI-элемент из `shadcn/ui`:

  | Тип поля          | Компонент shadcn/ui                           |
  | ----------------- | --------------------------------------------- |
  | string (короткий) | Input                                         |
  | string (длинный)  | Textarea                                      |
  | number            | Input с type="number"                         |
  | boolean           | Switch или Checkbox                           |
  | enum / union      | Select                                        |
  | Массив строк      | Повторяемый Input с кнопками добавить/удалить |

- [ ] Каждое поле оборачивай в FormField / FormItem / FormLabel / FormMessage из shadcn (если они есть в проекте), либо в обычный div с label.
- [ ] Используй `register` или `Controller` из `react-hook-form` для привязки полей.

---

### 6. Логика сохранения изменений из BlockEditor

- [ ] Кнопка «Применить» внутри `BlockEditor` вызывает `handleSubmit` из `react-hook-form`.
- [ ] В `onSubmit`-колбеке вызывай `onSave(block.id, formData)`.
- [ ] В `AdminPanel` обработчик `onSave` обновляет `props` нужного блока в state холста (найди блок по `id` и замени его `props`).
- [ ] После сохранения панель не закрывается — пользователь может продолжить редактирование.

---

### 7. Обнови кнопку «Сохранить» в AdminPanel

- [ ] При клике на главную кнопку «Сохранить» — выполни `console.log` с актуальным состоянием всех блоков холста, включая обновлённые `props`:
  ```json
  [
    { "id": "block-1", "type": "HeroSection", "props": { "title": "Hello" } },
    { "id": "block-2", "type": "EventCard", "props": { "date": "2024-01-01", "isVisible": true } }
  ]
  ```

---

### 8. Обнови layout AdminPanel

- [ ] Итоговый layout страницы должен иметь три зоны:
      [ Левая панель (палитра) ] [ Холст (canvas) ] [ Правая панель (BlockEditor) ]
- [ ] Правая панель появляется только при `selectedBlockId !== null`.
- [ ] Используй CSS Grid или Flexbox через Tailwind-классы.

---

### 9. Финальная проверка

- [ ] Клик по блоку на холсте открывает BlockEditor с формой для этого блока.
- [ ] Форма предзаполнена текущими значениями `props` блока.
- [ ] Все поля корректно редактируются через UI-компоненты shadcn.
- [ ] После нажатия «Применить» данные блока обновляются в state.
- [ ] Кнопка «Сохранить» выводит корректный `console.log` с актуальными `props` всех блоков.
- [ ] Нет TypeScript-ошибок. Типы берутся из `/types/blocks`.
- [ ] Не добавлено ни одной новой зависимости.
